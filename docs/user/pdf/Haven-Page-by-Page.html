Purpose

Sign in to the Haven identity console — lab demo, local console user, or single sign-on against the plane.

When to use it

  • Operate Login when your job matches this screen
  • Prefer Command Deck after login if you are unsure where to start
  • Confirm the identity server shows as connected in the sidebar status chip

How to get there

  • Route: /login
  • Nav: Unauthenticated → /login

Operate from the console (UX)

  1. Open http://<host>:30742/login.
  2. Confirm This machine context on the page (host, origin, protocol) so you know which console you are signing into.
  3. Lab / test: when HAVEN_LAB_LOGIN is enabled, a lab banner shows demo / demo and a one-click fill control.
  4. Or Sign in with single sign-on, or HAVEN_CONSOLE_USER+PASSWORD.
  5. Sign in — failures show an inline error.
  6. Empty / fail: Wrong password → check HAVEN_CONSOLE_* (or the plane's platform-idp secret for single sign-on); lab demo cannot change its own password.
  7. Success: Redirect to Command Deck; sidebar shows the identity server as connected.

Console: http://<host>:30742/ · Health: GET /api/v1/health. Never publish lab IPs — use <host>.

Purpose

When to use it

  • Operate Command Deck when your job matches this screen
  • Prefer Command Deck after login if you are unsure where to start
  • Confirm the identity server shows as connected in the sidebar status chip

How to get there

  • Route: /deck
  • Nav: Sidebar → Command Deck

Operate from the console (UX)

  1. Land on /deck after sign-in.
  2. Read the connected identity-server strip (URL, version, realm count).
  3. Scan orbit cards: identity server, Phase, Postgres, backup, certificate, login RPS.
  4. Follow Reconcile Timeline conditions (DatabaseReady, CertificateReady, IdentityProviderReady).

  7. Empty / fail: Not connected → Settings; external plane may show Ready with Postgres external — expected.
  8. Success: Connected banner + Ready phase (or understood external mode).

Purpose

Create an IdentityPlane when the console has cluster write RBAC, or bootstrap the first realm against the connected identity server when it does not.

When to use it

  • Operate Deploy wizard when your job matches this screen
  • Prefer Command Deck after login if you are unsure where to start
  • Confirm the identity server shows as connected in the sidebar status chip for realm bootstrap

How to get there

  • Route: /deploy
  • Nav: Sidebar → Deploy wizard

Operate from the console (UX)

  1. Open /deploy.
  2. The title reflects capabilities:
    • Deploy identity plane — console can create IdentityPlane CRs.
    • Bootstrap first realm — no create RBAC; durability/routing are informational only.
  3. Walk audience / profile / hostname / admin steps.
  4. Submit:
    • Plane mode → POST /api/v1/planes → Command Deck.
    • Realm mode → creates realm + haven-console client + optional admin user in the identity server.
  5. Empty / fail: 403/409 on plane create → apply sample CR or fix RBAC; realm mode needs the identity server connected.
  6. Success: Plane appears on Deck/Planes, or Realm Studio opens the new realm.

Console: http://<host>:30742/ · Health: GET /api/v1/health. Never publish lab IPs — use <host>.

Purpose

Check the identity-server connection and manage console appearance / passwords.

When to use it

  • Operate Settings when your job matches this screen
  • Prefer Command Deck after login if you are unsure where to start
  • Confirm the identity server shows as connected in the sidebar status chip

How to get there

  • Route: /settings
  • Nav: Sidebar → Settings

Operate from the console (UX)

  1. Open /settings (from Deck / Realm Studio when the identity server shows offline).
  2. If the identity server is offline, check the console's HAVEN_IDP_URL and admin client secret (see Console).
  3. Or enter any Admin API URL → Test & connect; expect a green Connected banner.
  4. Change the console password via the dialog (persist secrets before restart).
  5. Empty / fail: Connection failed → URL/network/admin creds; lab demo cannot change its password.
  6. Success: Connected to … · v… · N realms; Deck status goes green. OIDC SSO uses the connected URL when HAVEN_OIDC_ISSUER is unset.

Console: http://<host>:30742/ · Health: GET /api/v1/health. Never publish lab IPs — use <host>.
